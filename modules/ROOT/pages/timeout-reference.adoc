= Timeout Reference for Runtime Fabric on OpenShift

When a request times out on a deployment that uses Runtime Fabric on OpenShift, the error you see depends on which layer in the stack enforces the timeout. Use the reference below to identify which setting governs each layer so you can adjust the correct value.

== Timeout Layers

This table lists the timeout settings for each layer in the stack, from the OpenShift cluster ingress down to the Runtime Fabric agent.

[%header%autowidth.spread]
|===
|Layer |Setting |Default |Where Configured |Error When Exceeded

|OpenShift cluster (HAProxy)
|`haproxy.router.openshift.io/timeout`
|30s
|Route annotation
|504 Gateway Timeout

|Omni Gateway — upstream response
|`FLEX_UPSTREAM_RESPONSE_TIMEOUT_SECONDS` +
Response Timeout policy +
`spec.timeouts.upstreamResponseSeconds`
|15s
|Environment variable, policy, or `Configuration` resource
|504 Gateway Timeout

|Omni Gateway — upstream idle
|`FLEX_UPSTREAM_CONNECTION_IDLE_TIMEOUT_SECONDS` +
Upstream Idle Timeout policy +
`spec.timeouts.upstreamConnectionIdleSeconds`
|60s
|Environment variable, policy, or `Configuration` resource
|Connection reset

|Omni Gateway — stream idle
|`FLEX_STREAM_IDLE_TIMEOUT_SECONDS` +
Stream Idle Timeout policy +
`spec.timeouts.streamIdleSeconds`
|300s
|Environment variable, policy, or `Configuration` resource
|Connection reset

|Anypoint Code Builder — Deploy Project command
|Not configurable
|600s (10 min)
|—
|Error 3018

|Runtime Fabric agent reconcile
|Not configurable
|10 min
|—
|Silent pod failure
|===

For Omni Gateway timeout configuration details, see xref:gateway::conn-timeout.adoc[Configuring Timeouts].

For OpenShift Route annotation details, see the https://docs.openshift.com/container-platform/latest/networking/routes/route-configuration.html#nw-route-specific-annotations_route-configuration[Red Hat OpenShift documentation^].

== Troubleshoot Error 3018

Error 3018 occurs when the Anypoint Code Builder Deploy Project command exceeds its 600-second timeout. If all previous deployment steps succeeded but the deploy step fails with error 3018, follow this sequence to identify the root cause:

. Check whether OpenShift rejected pods due to a namespace resource quota. In your terminal, run:
+
[source,copy]
----
oc get events -n <namespace> --sort-by='.lastTimestamp'
----
+
Look for `FailedScheduling` events. If you see them, increase the namespace resource quota and retry the deployment.
. If no scheduling failures appear, check that the Runtime Fabric agent can reach Anypoint Platform. Verify that outbound network access to your Anypoint Platform control plane URL is not blocked.
. If network access is not the issue, contact MuleSoft Support and include the Runtime Fabric agent logs.
